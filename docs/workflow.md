# Workflow: конвейер проверки проекта

## Порядок шагов
Дирижёр → Разработчик → Тестировщик → Ревьюер → Документатор → Дирижёр (итоговый отчёт)

## Что передаётся между шагами
| Шаг | Агент | Получает | Отдаёт дальше |
|-----|-------|----------|---------------|
| 1 | Дирижёр | задачу / цель проверки | План (3–5 пунктов) |
| 2 | Разработчик | План | Список изменений |
| 3 | Тестировщик | Список изменений | Отчёт тестов + Итог PASS/FAIL |
| 4 | Ревьюер | Изменения + отчёт тестов + git diff | Замечания + Вердикт |
| 5 | Документатор | Изменения + Вердикт | Обновлённый README.md |
| 6 | Дирижёр | все отчёты | Итоговая сводка |

## Правило возврата при падении тестов
- Если Тестировщик вернул FAIL, работа возвращается Разработчику вместе со списком упавших проверок.
- После исправления снова запускается Тестировщик.
- Максимум 2 возврата. Если после 2-го возврата всё ещё FAIL, конвейер идёт к Ревьюеру, а в итоговом отчёте ставится пометка "Тесты не прошли после 2 итераций".

## Правило шага
Следующий агент не начинает работу, пока предыдущий не выдал ответ в своём формате.
